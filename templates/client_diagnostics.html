The default report omits hostnames, addresses, cookies and entry tokens. It tests A/AAAA/HTTPS/SVCB, TCP 443, verified TLS, the unauthenticated entry redirect and code page. It never activates a code or changes policy. An optional --resolver override or --ca file tests that explicit path only.

Phone, tablet and browser acceptance

  1. Use the affected Wi-Fi/VPN connection and check the device uses your intended DNS. Disable a conflicting custom Secure/Private DNS setting for this controlled test.
  2. Install the device CA from the portal. On iOS also enable full trust for that root. Verify the device clock.
  3. Use a private browser window with no active code/admin login. An IP exclusion must not cover this test device.
  4. Open the selected restricted hostname. Expect trusted HTTPS followed by the code-entry page. Do not enter a code for this test.
  5. Record whether the failure is DNS, refused connection, certificate warning or missing portal. Compare with the client report and System status.
